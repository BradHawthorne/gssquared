# indirectjumptest fixture: JMP (a,x) ($7C) and JSR (a,x) ($FC), one instruction per case.
#
# case <name> pc= s= p= a= x= y= dbr= d= pbr= e=   initial registers (hex)
# init <addr24>=<byte> ...      initial memory (everything else is zero)
# want <reg>=<hex> ... cycles=<decimal>   expected registers and cycle count after one instruction
# wantmem <addr24>=<byte> ...   expected memory bytes
# end
#
# Rule under test: the pointer for JMP (a,x) / JSR (a,x) is read from the program bank, and both of its
# bytes stay in that bank: a+X wraps at $FFFF, and a pointer at $FFFF takes its high byte from $0000 of the
# same bank (not of the next bank). hand-* cases were worked by hand; each wrap case has a decoy byte in
# the next bank. sst-* cases are vectors from the SingleStepTests ProcessorTests 65816 v1 set (MIT licence,
# upstream commit bb11756436da8fd16cce86aef63dc6725f48836f; e.g. sst-fcn7140-wrap is "fc n 7140" of fc.n.json):
# "wrap" = every vector of 7c.n/7c.e/fc.n/fc.e whose pointer sits at $FFFF, "ctl" = the first 3 others of
# each file. For e=1 the initial S, P, X, Y are given with the 65816 invariant applied (SH=$01, M=X=1,
# XH=YH=0). fc.e controls avoid S=$0100 (a separate emulation-mode stack-wrap question, not tested here).

# JMP (a,x), native x=0: pointer at 05:FFFF, high byte from 05:0000 (06:0000 is a decoy)
case hand-jmp-ptr-ffff pc=1000 s=1FF p=0 a=0 x=F y=0 dbr=0 d=0 pbr=5 e=0
init 051000=7C 051001=F0 051002=FF 05FFFF=34 050000=12 060000=EE
want pc=1234 pbr=5 s=1FF cycles=6
end

# JSR (a,x), native x=0: pointer at 05:FFFF; return address $2002 pushed at 00:01FF/01FE
case hand-jsr-ptr-ffff pc=2000 s=1FF p=0 a=0 x=1 y=0 dbr=0 d=0 pbr=5 e=0
init 052000=FC 052001=FE 052002=FF 05FFFF=78 050000=56 060000=EE
want pc=5678 pbr=5 s=1FD cycles=8
wantmem 0001FF=20 0001FE=02
end
