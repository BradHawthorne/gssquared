# blockmovetest fixture: MVN ($54) / MVP ($44) cases with independent expected values.
#
# case <name> op=<54|44> e= p= a= x= y= s= d= dbr= pbr= pc= moves=<n>   initial registers (hex), n = instructions to run
# init <addr24>=<byte> ...      initial memory (everything else is zero)
# want a= x= y= dbr= pc= cycles=  expected registers after n executions (x/y compared as full 16-bit values,
#                                 so a high byte left non-zero under x=1 or e=1 fails); cycles = 7 per byte moved
# wantmem <addr24>=<byte> ...   expected memory bytes after the run
# end
#
# hand-* cases were worked by hand from the datasheet rule: with x=1 (always so in emulation mode) the index
# registers are 8 bits wide, so MVN/MVP address $00-$FF of the source/destination banks and X/Y wrap within
# 8 bits; DBR becomes the destination bank; each execution moves one byte and decrements A; the move ends
# (PC past the operands) when A wraps from $0000 to $FFFF, otherwise PC stays on the opcode.
#
# sst-* cases are vectors from the SingleStepTests ProcessorTests 65816 v1 set (MIT licence, upstream commit
# bb11756436da8fd16cce86aef63dc6725f48836f; the name gives file and vector number, e.g. sst-54n-wrap-18 is
# "54 n 18" of 54.n.json). Those vectors run a fixed 100-cycle bus budget, so a move that is still running is
# stopped 1-3 cycles into its next iteration; here only the n whole iterations are run and the expected pc is
# the opcode address (SST's final pc less those fetch cycles). For e=1 the initial S, P, X, Y are given with
# the 65816 invariant applied (SH=$01, M=X=1, XH=YH=0); the SST file's raw values may differ there.
# "wrap" = X or Y crosses $FF/$00 during the move with 8-bit index registers; "nowrap" = it does not;
# "x16" = 16-bit index registers (control); "done" = the move finishes inside the vector.

end
